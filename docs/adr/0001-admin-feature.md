# 管理者機能の権限判定とユーザー一覧の実体

管理者向けの `/admin` ページ(全ユーザーの出社率統計・閾値による抽出)を追加するにあたり、以下を決定した。

- **管理者判定**: Cloudflare AccessのグループやD1のroleカラムではなく、Worker環境変数(`vars`/secret)に列挙した管理者メールアドレスのリストとの照合で行う。既存の認証はAccessに一本化済みで役割(role)の概念がなく、D1にも`users`テーブルが存在しない([migrations/0002_access_auth.sql](../../workers/api/migrations/0002_access_auth.sql)でユーザー登録テーブルごと削除済み)。Access側の設定変更やD1スキーマの再導入をせず、最小の変更で完結させるためこの方式を選んだ。
- **ユーザー一覧の実体**: `attendance_records`テーブルにDISTINCTな`user_id`として登場するメールアドレスの集合を「全ユーザー」とみなす。ユーザー登録の仕組みが存在しないため、Accessで認証されうる全メールアドレスをWorker側から知る手段がない。「出社率統計」という機能の性質上、勤怠記録が1件もないユーザーを一覧に含める意味もないため、この定義を採用した。
- **集計期間**: 各ユーザー自身の`closingDay`/`closingDayShift`設定に基づく「現在の期間」を使い、`offsetMonths`によるページ全体共通のナビゲーションを提供する。全ユーザー共通の暦月に揃える案もあったが、個人画面に表示される数値と一致させることを優先した。
- **ドリルダウンは読み取り専用**: 管理者はユーザーごとのカレンダー/日別記録を閲覧できるが、代理編集はできない。編集を許すと「本人が付けたか管理者が付けたか」を区別する監査の仕組みが別途必要になるため、v1では見送った。
